## 振り返り（KPT）

### Keep（効いた・次も続ける）
- Gate1提示済みの要件チェックリストとspec（index.md）のAC文言を突き合わせる自己チェックが、Gate2提示前に3件の記載漏れを自己発見できた。仕様確定時の照合ステップとして有効
- 3体並列セルフレビューが、単一のCodex実装セッションでは発見しづらい「計画外の混入」「タスク分解の漏れ」を独立に検出した。特に「3体全員が同じ問題を指摘する」というシグナルは、裏取りの優先度判断に有効だった
- Codexへの委譲プロンプトに「他ファイルへの旧文言依存を`grep`で確認する」という明示指示を加えたT7では、T6と同型の回帰がCodex自身の事前確認で防がれた（学びを次のタスクへ即座に反映できた）
- git分離作業（`git restore --staged`＋`Edit`での一時的なテストコード除去→stage→復元）で、同一ファイル内に混在した「関連コミット」と「無関係コミット」の変更を正確に切り分けられた

### Problem（詰まった・摩擦・想定外）
- `[review]` **spec作成時の実装配置洗い出しが、共有コンポーネントへの変更の波及先まで追いきれなかった**。`TagBadge`（AC-6対象）の変更が`TodoListItem.tsx`側のテストに影響することを、ui.md執筆時に想定できていなかった
- `[review]` **タスク分解（progress.mdのT1〜T7）が、1つのACを複数コンポーネントに跨って実装する場合の担当漏れを防げなかった**。AC-10はTodoListPageとTagManagementModal双方に同一パターンのトーストがあったが、T1のタスク定義がTodoListPageのみを対象にしてしまい、TagManagementModal分が計画から抜け落ちた
- `[tooling]` **`git add -A`の多用が、コミット確定前の別タスクの変更を意図せず巻き込むリスクを生んだ**。本ユニットの一連の委譲サイクル（T1〜T7）で毎回`git add -A`（後に`git add docs/ src/`等に変更）を実行していたが、その過程でコミット承認待ちだった別タスク（レイアウト崩れバグ修正）の変更が繰り返しstageされ続け、最終的にセルフレビューで検出されるまで気づかなかった
- `[tooling]` **`wrangler.jsonc`のdatabase_id変更が、ローカル開発環境を無警告で壊す**。本番デプロイのための正当な変更だったが、ローカルのD1エミュレーションストレージがIDごとに分離される仕様を認識しておらず、ユーザーから「ローカルが動かなくなった」と報告されるまで気づかなかった
- `[review]` 最初のfork委譲（デザイン比較調査）が実質空振りに終わった。原因は特定できていないが、313kトークンという大きなコストを消費して有用な出力がゼロだった

### Try（次ボルト以降でフローをこう変える）
- spec作成（Stage2）で共有コンポーネント（`TagBadge`等、複数箇所から呼ばれるコンポーネント）を変更する場合、変更前に`grep -rn "<ComponentName>" src/`でそのコンポーネントの全呼び出し元を洗い出し、呼び出し元のテストファイルも「実装配置」または「テストケース」節に明記する運用を徹底する
- 1つのACが複数コンポーネントに同一パターンで存在する場合（今回のAC-10のトースト等）、タスク分解（progress.mdのT1〜T7）で「このACを担保する全コンポーネント」をチェックリスト化してから各タスクに割り付ける。Gate2提示時にAC×コンポーネントのマトリクスを作ると防げた可能性がある
- `git add -A`ではなく、常に対象ファイルを明示指定した`git add <files>`を使う運用を徹底する（task-and-pr.mdの「ワイルドカードや`-A`は使わず対象ファイルを明示的に指定する」という既存ルールを、AI-DLCの委譲サイクル中の中間`git add`にも一貫して適用する）
- `wrangler.jsonc`のdatabase_id等インフラ設定を変更する際は、変更直後に`pnpm db:migrate:local`の再実行が必要になることをdeploy.mdに明記する（本ユニットの完了報告と同時にdocs/deploy.mdへ追記済み）
- forkが空振りした場合の切り替え判断（縮小リトライ1回→ダメならfresh general-purposeエージェントへ切り替え）を、ai-dlc-flow.mdの「受領検査と縮小リトライ」節に「forkが待機メッセージのみを返した場合」のケースとして明記することを検討する
