# quick-add: クイック追加

> TODO一覧からタイトルだけを入力して、作成モーダルを開かずにTODOを追加できるようにする。

## 概要

TODO一覧画面にタイトル専用のクイック追加フォームを追加する。入力したタイトルはEnterキーで既存の`POST /api/todos`へ送信し、成功後は入力欄を空に戻す。

## 対象範囲

- 対象レイヤー: [ui.md](./ui.md)
- 対象ドメイン: TODO作成の短縮導線
- 対象外:
  - TODO作成API、DBスキーマ、認証の変更
  - 説明・優先度・期限・タグをクイック追加から入力する機能
  - キーボードショートカットや外部クライアントからの追加
  - 既存の詳細作成モーダルの削除・置換

## ユニット計画

単一ユニットで完結する。

## 受け入れ基準（AC）

- [ ] **AC-1**: TODO一覧画面にタイトル入力欄を含むクイック追加フォームが表示される。
- [ ] **AC-2**: タイトルを入力してEnterキーを押すと、既存の`POST /api/todos`へタイトルのみを送信できる。
- [ ] **AC-3**: 作成成功時、入力欄が空になり、既存の一覧キャッシュ無効化により新しいTODOが一覧へ反映される。
- [ ] **AC-4**: 空文字、空白のみ、201文字以上の入力ではリクエストを送信せず、フォーム内に入力エラーを表示する。
- [ ] **AC-5**: 作成中は二重送信を防止し、APIエラー時は入力内容を保持したままフォーム内に再試行可能なエラーを表示する。
- [ ] **AC-6**: フォームはPC・タブレット・スマートフォンで使用でき、入力欄・ボタンのタップ領域は既存の44px規約を満たす。

## アーキテクチャ / レイヤー間フロー

```text
QuickTodoInput
  → useCreateTodo()
  → POST /api/todos（既存）
  → 成功: TODOS_QUERY_KEYをinvalidate → 入力欄をクリア
```

## エラー・ログ方針（横断サマリ）

| シナリオ | UIの挙動 |
|---|---|
| クライアント入力不正 | リクエストを送らず、フォーム内に入力エラーを表示 |
| API 400 | 入力を保持し、「入力内容を確認してください」を表示 |
| API 500 / ネットワークエラー | 入力を保持し、「時間をおいて再度お試しください」を表示 |

## テスト戦略

| AC | 単体 | レイヤー内結合 |
|---|---|---|
| AC-1〜AC-6 | — | `QuickTodoInput`の入力・送信・成功・失敗・二重送信防止 |

## 既存実装との関係（再利用 / 差分 / 衝突）

- `useCreateTodo()`を再利用し、成功時の`TODOS_QUERY_KEY`無効化を既存のまま利用する。
- `createTodoSchema`をクライアント側の入力検証に再利用する。
- 詳細な属性入力は既存の`TodoFormModal`へ委ねる。
- 新しいAPI・共有型・DB変更はない。

## 実装に効く制約

- クイック追加の送信payloadはタイトルのみとし、その他の属性は既存APIのデフォルトに任せる。
- タイトルは前後空白をtrimしてから検証・送信する。
- Enterキーによる通常のフォーム送信を使い、独自のグローバルキーボードリスナーは追加しない。
- 成功時のみ入力欄をクリアし、失敗時は入力内容を保持する。

## 判断根拠 / 未決事項

- モーダルを開く操作を省くことが目的のため、タイトル専用のインラインフォームを採用する。
- モーダルの全項目をクイックフォームへ複製する案は、入力負荷と保守範囲を増やすため採用しない。
- 既存APIのデフォルト値と入力スキーマを再利用するため、service層へ変更を広げない。
- 未決事項はない。
