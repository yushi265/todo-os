# quick-add: ui 詳細設計

## 担保 AC（[index.md](./index.md) の AC からの引用）

- **AC-1**: TODO一覧画面にタイトル入力欄を含むクイック追加フォームが表示される。
- **AC-2**: タイトルを入力してEnterキーを押すと、既存の`POST /api/todos`へタイトルのみを送信できる。
- **AC-3**: 作成成功時、入力欄が空になり、既存の一覧キャッシュ無効化により新しいTODOが一覧へ反映される。
- **AC-4**: 空文字、空白のみ、201文字以上の入力ではリクエストを送信せず、フォーム内に入力エラーを表示する。
- **AC-5**: 作成中は二重送信を防止し、APIエラー時は入力内容を保持したままフォーム内に再試行可能なエラーを表示する。
- **AC-6**: フォームはPC・タブレット・スマートフォンで使用でき、入力欄・ボタンのタップ領域は既存の44px規約を満たす。

## UI/UX 方針

- **画面フロー / 導線**: ヘッダーと検索・フィルターバーの間に常時表示し、入力→Enter→一覧反映の1ステップで完了する。既存の詳細作成ボタンも残す。
- **主要操作とフィードバック**: 送信中は二重送信を防止する。成功時は入力をクリアし、失敗時は入力とエラーを保持する。
- **状態設計（出し分け）**: 初期は空入力、入力中は送信可能、送信中は二重送信不可、入力エラー/APIエラーはフォーム直下、成功後は空入力へ戻る。
- **既存デザインシステムとの整合**: 既存の`border`、`bg-card`、`rounded-xl`、`min-h-11`、`primary`トークンを再利用する。

### レスポンシブ / アクセシビリティ

- PC・タブレット・スマートフォンで横幅に応じて入力欄を伸縮させる。フォームは`flex`と`flex-wrap`で狭い幅でも崩さない。
- 入力欄に`label`を紐付け、`aria-label="クイック追加"`を設定する。
- 入力欄に`min-h-11`を付け、フォームのEnter送信を使用する。
- エラーは`role="alert"`で読み上げ可能にする。

## 異常系挙動

| シナリオ | UIの挙動 |
|---|---|
| タイトルが空または空白のみ | フォーム内に「タイトルは1〜200文字で入力してください」を表示し、APIを呼ばない |
| タイトルが201文字以上 | 同じ入力エラーを表示し、APIを呼ばない |
| APIエラー | 送信前のタイトルを保持し、エラー種別に応じたメッセージを表示 |

## テストケース（技法注記付き）

- [代表値] タイトル入力後にEnter → `POST /api/todos`へタイトルのみ送信
- [代表値] 追加ボタンを使わずEnter → `POST /api/todos`へタイトルのみ送信
- [境界値] 空文字、空白のみ、200文字 → 入力エラーまたは送信成功、201文字 → 入力エラー
- [状態遷移] 送信成功 → 入力クリア、送信失敗 → 入力保持
- [異常系] API 400 / 500 → フォーム内エラー表示
- [境界値] 送信中の追加操作 → リクエストが1回だけ発生
