# high-priority-backlog: 表示層詳細設計

## 公開契約

`QuickTodoInput`は任意の`tags: TagResponse[]`を受け取る。`TodoListPage`は既に取得したタグ一覧を渡し、クイック追加内でタグ一覧を再取得しない。

一覧のタグ絞り込み状態は`localStorage`の`todo-os-tag-filter`へ保存し、画面再読み込み後も復元する。「すべて」を選択した場合は保存値を削除する。

## UI方針

- クイック追加はタイトル入力・タグ選択・追加ボタンを同じ主行に置き、タグ選択は追加ボタンの直前にネイティブ`select`として配置する。
- クイック追加側のセレクトは「追加時のタグ」、一覧側の見出しは「一覧を絞り込む」とし、TODOへ付与する操作と一覧表示を絞る操作を明確に区別する。
- タグ未選択時は「タグなし」を表示し、既存タグを1つ選択してTODOへ付与できる。選択状態は`select`の値で示す。
- 一覧を絞り込むタグ切替は画面上部でメニューボタンと同じ行に置き、クイック追加より上に配置する。メニューボタンはアイコンのみを表示し、ARIA名と`title`で「メニュー」を維持する。
- ブランド表示を含むヘッダー枠は置かず、一覧上部にはPC向けの通常追加ボタンとメニューを開くボタンを配置する。設定・完了表示・タグ管理はメニュー画面（右側サイドパネル）にまとめる。
- メニュー画面は右側からスライドインして表示する。`prefers-reduced-motion`ではアニメーションを抑制する。
- クイック追加と検索操作の間には余白を設ける。検索・フィルター・並び順の行は初期状態で折りたたみ、メニュー内の「検索・フィルターを表示」スイッチで開閉する。開いた行は検索をモバイルで全幅、フィルター操作と並び順は別行へ折り返し、`sm`以上は横方向の配置を維持する。
- 「残りN件」は削除し、一覧上部の入力・絞り込み・操作欄の余白で階層を保つ。

## 送信仕様

| 状態 | POST `/api/todos` body |
|---|---|
| タグ未選択 | `{ "title": "..." }` |
| タグ選択あり | `{ "title": "...", "tagIds": [1] }` |

作成成功時はタイトルだけをクリアし、タグ選択は次のクイック追加にも引き継ぐ。失敗時は入力と選択を保持する。

## テストケース

- クイック追加のセレクトで既存タグを選択・解除できる。
- タグ選択ありの送信payloadに`tagIds`が含まれる。
- タグ選択ありで作成成功しても、タイトルだけがクリアされタグ選択は維持される。
- タグ未選択の既存タイトル専用payloadが変わらない。
- 一覧を絞り込むタグ切替がクイック追加より上に表示される。
- 選択したタグ絞り込みが`localStorage`へ保存され、再マウント後に復元される。「すべて」で保存値が削除される。
- ブランド表示を含むヘッダーが存在せず、「残りN件」も表示されない。メニューは`role="dialog"`で開閉状態を示し、Escapeと閉じるボタンで閉じられる。
- メニュー内の検索・フィルター表示スイッチが開閉状態を示し、一覧上部の検索・フィルター・並び順にモバイル用の縦配置クラスがある。
