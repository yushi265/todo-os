# design-conformance-polish: デザインとの見た目乖離の是正

> 薄い実装 spec の入口。読み手は人間（Gate 1/2/3 承認者）。AI 実装エージェント（Codex）は [ui.md](./ui.md) を読む。

## 概要

Claude Design「TodoOS v2.dc.html」（PC版）・「TodoOS Mobile.dc.html」（モバイル版）と現行実装（Unit3〜6で構築）を全コンポーネント横断で比較調査した結果、多数の見た目の乖離が判明した。本ユニットはこれらをデザイン準拠に是正する。ユーザー判断により、Unit3で追加した機能拡張（ステータス進行ショートカット・行の削除ボタン）は維持し、見た目（サイズ・配色・構造）のみデザインに寄せる。

## 対象範囲

- 対象レイヤー: ui のみ（[ui.md](./ui.md)）
- 対象ドメイン: TODO一覧画面の全コンポーネント（ヘッダー・フィルターバー・各モーダル・タグ表示・完了トグル・空状態・トースト）の見た目
- 対象外（やらないこと）:
  - API・データスキーマ・レイヤー間インターフェースの変更（見た目のみの是正）
  - ステータス進行ショートカットボタン・行の削除ボタン（Unit3の機能拡張）の削除・簡略化（ユーザー判断で維持）
  - タッチターゲット最小44px（`min-h-11`/`min-w-11`）をデザインの視覚サイズに合わせて44px未満へ縮小すること（アクセシビリティ優先。デザインの視覚サイズに近づけられる範囲〈パディング・トラック外形等〉でのみ対応し、タップ可能領域は44px以上を維持する）
  - 横スクロール可能なフィルターチップ列の採用（Unit4で見送り済み、`flex-wrap`折り返しを継続）

## ユニット計画

単一ユニット（本 spec で完結）。

## 受け入れ基準（AC）

- [ ] **AC-1**: ヘッダー（`TodoListPage.tsx`）に、デザイン通りの色付き正方形ロゴアイコン（`background:#4f46e5`、角丸）と「残り{N}件」のアクティブTODO件数表示が、タイトル文字列と並んで表示される。
- [ ] **AC-2**: 検索・フィルター・ソートバー（`TodoFilterBar.tsx`）から、デザインに存在しない外枠カード（`rounded-2xl border ... bg-card`）を除去し、検索入力に虫眼鏡アイコンが表示され、フィルターチップ・「＋フィルター」ボタン・ソートセレクト・方向切替ボタンがピル型（`rounded-full`）で統一される。
- [ ] **AC-3**: TODO作成/編集モーダル（`TodoFormModal.tsx`）で、モーダル背景オーバーレイに半透明のぼかし演出（`backdrop-blur`）が適用され、説明欄に適切な初期表示行数（`rows`属性）が設定され、「✓ 完了にする」ボタンがステータスセレクトと同じ行に横並び配置され、タグ選択トグル（`TagMultiSelect.tsx`）の選択済みタグがアクセントカラー（primary）で強いコントラストの配色になる。
- [ ] **AC-4**: タグ管理モーダル（`TagManagementModal.tsx`）で、閉じるボタンが円形の背景付きボタンになり、タグ行が個別のカード型（背景色・角丸・行間の隙間あり）で表示され、タグ名編集中の入力欄ボーダーがアクセントカラー（primary）に変化する。
- [ ] **AC-5**: 削除確認ダイアログ（`DeleteConfirmDialog.tsx`）が、PC・モバイル両方の画面幅で常に画面中央のセンタリング表示になる（モバイル幅でのボトムシート化をやめる）。
- [ ] **AC-6**: タグバッジ（`TagBadge.tsx`ほかタグ名を表示する全箇所）が「#」プレフィックス付きでタグ名を表示し、完了・キャンセル済みTODO行のタグバッジは未完了行より薄い色で表示される。
- [ ] **AC-7**: 完了表示トグル（`CompletedToggle.tsx`）が「スイッチ→ラベルテキスト」の順で表示され、ラベル文言がデザイン通り（「完了・キャンセル済みを表示」）になり、タップ可能領域44px以上を維持しつつスイッチの視覚サイズがデザインに近い外形になる。
- [ ] **AC-8**: 空状態表示（`TodoListPage.tsx`）で、「＋最初のTODOを追加」ボタンが`sm`以上（PC/タブレット）でのみ表示され、モバイル幅では表示されない（FABが作成導線を担うため）。加えて、空状態の枠に水平方向のpadding（デザイン相当の余白）が追加される。
- [ ] **AC-9**: 主要なCTAボタン（保存・追加・削除する・＋追加・＋最初のTODOを追加）が太字（`font-bold`/`font-weight:700`相当）で表示され、デザインでフォントサイズが明示されている主要なラベル・ボタン文字（ヘッダーの「タグ管理」ボタン等）がブラウザ既定サイズではなく意図したサイズで表示される。
- [ ] **AC-10**: トースト通知（`TodoListPage.tsx`）に表示時のフェード+スライドインアニメーションが適用され、シャドウがデザイン相当の強さになり、モバイル幅ではFAB（画面右下固定ボタン）と重ならない位置に表示される。

## アーキテクチャ / レイヤー間フロー

本ユニットはUIレイヤー内の見た目調整のみで、サービス層・データ層とのフローに変更はない。既存のAPI呼び出し・状態管理ロジックはそのまま維持する。

## エラー・ログ方針（横断サマリ）

見た目のみの変更であり、エラー・ログ方針に変更はない。既存の異常系挙動（Unit3〜6で確立済み）をそのまま継承する。

## テスト戦略

| AC | 単体 | レイヤー内結合 |
|----|------|--------------|
| AC-1〜AC-10 | — | 対象（各コンポーネントのレンダリング結果に対するクラス・要素の存在確認・属性値確認） |

見た目（CSS classやDOM構造）の検証が中心のため、既存の各コンポーネントテストファイルへのテストケース追加で担保する（新規レイヤーは発生しない）。ケース詳細は [ui.md](./ui.md) の「テストケース」節を参照。

## 既存実装との関係（再利用 / 差分 / 衝突）

- **再利用**: 全コンポーネントの構造・props・イベントハンドラ・状態管理ロジックはそのまま。`index.css`の`@theme`色トークン定義はデザインと一致済みのためトークン自体の追加・変更は不要（使用箇スタイルの選択のみ是正）。
- **差分**: 本spec「受け入れ基準」に列挙した10項目。詳細な調査結果（デザインHTML vs 実装コードの具体的な差分）はGate2提示時に共有する。
- **衝突**: なし。Unit3の機能拡張（ステータス進行ショートカット・削除ボタン）は維持するため、それらに依存する既存テストとの衝突はない。

## 実装に効く制約

- タッチターゲット最小44px（`min-h-11`/`min-w-11`）はどの要素でも縮小しない（対象外節を参照）。
- ステータス進行ショートカットボタン・行の削除ボタンの機能・配置・イベントハンドラは変更しない。デザインに存在する要素（ドットインジケーター等）を追加する場合も、既存の機能を壊さない形で行う。
- `index.css`の`@theme`色トークンは追加・変更しない。既存トークンの中から、デザインの意図に合う適切なトークンを選び直す（例: スイッチOFF色は`bg-border`ではなく`border-dashed`相当のトークンを検討）。
- Tailwindのユーティリティクラスのみで実現し、新規CSSファイル・インラインstyleは追加しない（既存の実装方針を踏襲）。

## 判断根拠 / 未決事項

- **全部まとめて1ユニットで対応**: ユーザー判断（2026-08-15）。段階分割よりも一括対応を選択。ただし実装タスクは`progress.md`でコンポーネント単位に順序分解し、Codexへの委譲は複数回に分けて行う（レビュー可能性の確保）。
- **Unit3の機能拡張を維持**: ユーザー判断（2026-08-15）。デザインの「表示専用バッジ」路線には戻さず、見た目（配色・サイズ・ドットインジケーター等の装飾）のみデザインに寄せる。
- **44pxタッチターゲットは死守**: アクセシビリティ（iOS HIG/Android Materialのタッチターゲット推奨44-48px）を優先し、デザインの視覚サイズ（34-38px程度の要素が多い）に完全一致はさせない。視覚的なサイズ感の近似は、パディング調整や内部要素（トラック・ノブ等）のサイズ調整で対応する。
- **横断的なタイポグラフィ差分（AC-9）の扱い**: 個別コンポーネントごとにfont-size等のTailwindクラスを追加していく方針とし、グローバルなベーススタイル変更（`index.css`のbody font-sizeの変更等）は行わない（影響範囲を予測しやすくするため）。
