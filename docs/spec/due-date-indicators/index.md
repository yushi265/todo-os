# due-date-indicators: 期限表示の補完

> TODO一覧の期限表示を、期限切れ・本日・近日の3段階で視覚的に判別できるようにする。

## 概要

既存の期限日表示を拡張し、未完了TODOの期限が期限切れ・本日・近日の場合を絵文字で一覧上から判別できるようにする。
期限判定は既存のAsia/Tokyo基準を維持し、API・DBの契約は変更しない。

## 対象範囲

- 対象レイヤー: [ui.md](./ui.md)
- 対象ドメイン: TODO一覧の期限表示
- 対象外:
  - 期限日そのものの編集仕様変更
  - APIレスポンス、DBスキーマ、検索・フィルター条件の変更
  - 通知、リマインダー、ブラウザ通知

## ユニット計画

単一ユニットで完結する。

## 受け入れ基準（AC）

- [ ] **AC-1**: 未完了TODOの期限がAsia/Tokyo基準で本日より前の場合、期限日と期限切れを表す絵文字マーカーが危険色付きで表示される。
- [ ] **AC-2**: 未完了TODOの期限がAsia/Tokyo基準の本日の場合、期限日と本日期限を表す絵文字マーカーが表示される。
- [ ] **AC-3**: 未完了TODOの期限が本日より後かつ3日以内の場合、期限日と近日を表す絵文字マーカーが表示される。
- [ ] **AC-4**: 期限なし、期限が4日以上先、または完了済みTODO（`DONE`/`CANCELED`）には期限の緊急度マーカーを表示せず、既存の期限日表示を維持する。
- [ ] **AC-5**: 期限判定ロジックは現在時刻を引数で差し替えてテストでき、日付境界とステータス条件を再現性のあるテストで検証できる。

## アーキテクチャ / レイヤー間フロー

```text
TodoListItem
  → dueDateStatus(dueDate, status, now)
  → 期限日 + 状態ラベル + 視覚マーカーを表示
```

## エラー・ログ方針（横断サマリ）

| シナリオ | UIの挙動 |
|---|---|
| 期限なし | 既存どおり「-」を表示し、マーカーを表示しない |
| 完了済みTODOの期限が過去 | 期限日を表示するが、期限の緊急度を表示しない |
| 不正な期限値 | serviceの既存バリデーション契約に委ね、UI側では新たな補正を行わない |

## テスト戦略

| AC | 単体 | レイヤー内結合 |
|---|---|---|
| AC-1〜AC-5 | `dueDateStatus`の判定、日付境界、ステータス条件 | `TodoListItem`の状態ラベル・マーカー表示 |

## 既存実装との関係（再利用 / 差分 / 衝突）

- 既存の`isOverdue`が持つAsia/Tokyo基準と未完了ステータスの方針を、期限状態判定へ拡張する。
- `TodoListItem`が既に表示している期限日を再利用し、期限状態ごとの絵文字マーカーだけを追加する。
- API・DBの契約および`TodoResponse`は変更しない。

## 実装に効く制約

- 「近日」は本日を除く3日以内（明日〜3日後）とする。
- 日付比較はAsia/Tokyo基準の`YYYY-MM-DD`文字列で行い、ブラウザのローカルタイムゾーンに依存しない。
- 完了済みTODOには緊急度を表示しない。
- 新規CSSトークンは追加せず、既存の`danger`、`primary`、`priority-medium`を再利用する。

## 判断根拠 / 未決事項

- 期限表示の既存契約がAsia/Tokyo基準であるため、近日判定も同じ基準に揃える。
- 「近日」の閾値は、過剰な通知感を避けつつ一覧で先回りできる3日以内を採用する。将来のリマインダー機能や閾値設定は対象外とする。
- 画面上は絵文字マーカーだけにして情報量を抑えつつ、絵文字にはスクリーンリーダー向けの`aria-label`を付与する。
- 未決事項はない。
