# subtasks: ui 詳細設計

## 担保 AC（[index.md](./index.md) の AC からの引用）

- **AC-1**: 既存 TODO の編集画面で、タイトル（1〜200文字必須）を指定してサブタスクを追加できる。追加したサブタスクは親 TODO に紐づいて保存され、通常の TODO 一覧には独立した行として表示されない
- **AC-2**: 親 TODO の取得レスポンスには、紐づくサブタスクが作成順で含まれる。TODO 一覧カードにはサブタスクの完了数/総数を表示する
- **AC-3**: 編集画面でサブタスクの完了状態を切り替えられ、変更が保存される。完了数/総数の表示も更新される
- **AC-4**: 編集画面でサブタスクを削除できる。親 TODO を削除した場合は、紐づくサブタスクも削除される
- **AC-5**: サブタスクのタイトルが空文字または201文字以上の場合、追加は400エラーとなり、既存データは変更されない。完了状態以外の不正な更新値も400エラーとなる
- **AC-6**: 存在しない親 TODO、存在しないサブタスク、または別の親に属するサブタスクへの操作は404エラーとなる
- **AC-7**: 既存 TODO の作成・取得・更新・削除・タグ・並び替えの挙動は、サブタスク未使用時も従来どおり維持される

## このレイヤーが公開する契約（外部インターフェース）

画面パスは既存の `/` のまま。編集モーダルを開いた時だけ、`GET /api/todos/:todoId/subtasks` を呼び出す。

| 操作 | API | UI | 用途 |
|---|---|---|---|
| 取得 | `GET /api/todos/:todoId/subtasks` | `useSubtasks(todoId)` | 編集画面の最新サブタスク表示 |
| 追加 | `POST /api/todos/:todoId/subtasks` | `useCreateSubtask()` | タイトル入力から追加 |
| 完了切替 | `PATCH /api/todos/:todoId/subtasks/:subtaskId` | `useUpdateSubtask()` | チェックボックス操作 |
| 削除 | `DELETE /api/todos/:todoId/subtasks/:subtaskId` | `useDeleteSubtask()` | サブタスク削除ボタン |

## このレイヤーが依存する下位の契約

- service のサブタスクAPI（[service.md](./service.md)）。認証情報は既存 API と同様に Cloudflare Access のCookieへ任せる。
- `SubtaskResponse` と `createSubtaskSchema` / `updateSubtaskSchema` は `src/shared/` から import する。

## UI/UX 方針

- **画面フロー / 導線**: TODO一覧の行を開いて編集モーダルを表示すると、フォーム下部に「サブタスク」欄を表示する。作成モーダルには表示しない。
- **主要操作とフィードバック**: 入力して「追加」で子を作成する。各行のチェックボックスで完了状態を即時保存し、削除ボタンで即時削除する。成功時はリストと親一覧をinvalidateして進捗を反映する。
- **状態設計（出し分け）**: 取得中は「サブタスクを読み込み中…」、0件は「サブタスクはありません」、取得失敗は欄内のエラーと「再試行」。入力不正は追加欄直下、404は「サブタスクが見つかりませんでした」、500は汎用エラーを表示する。
- **既存デザインシステムとの整合**: `ModalFrame`、既存の `Button`、既存のフォーム入力クラスと色トークンを再利用する。削除確認ダイアログは使わず、サブタスクは親編集画面内の小さな単位として即時削除する。

### レスポンシブ / アクセシビリティ

- PC・タブレット・スマートフォンを対象とし、既存モーダルの `sm` ブレークポイントとボトムシート表示を維持する。
- サブタスク行はモバイルでタイトルと操作を縦に潰さず、入力・チェックボックス・削除ボタンのタップ領域を44px以上にする。
- チェックボックスには `サブタスク「タイトル」を完了にする/未完了に戻す` の `aria-label`、削除ボタンには固有の `aria-label` を付ける。入力には `<label>` を紐付け、追加中はボタンをdisabledにする。

## 異常系挙動

| シナリオ | 本レイヤーの挙動（表示・ログ） |
|---|---|
| タイトル空/201文字 | 追加欄を閉じず、入力欄直下に「サブタスクは1〜200文字で入力してください」。APIは呼ばない |
| サブタスク取得失敗 | 欄内にエラーと再試行ボタンを表示 |
| 404 | 欄内に「サブタスクが見つかりませんでした」を表示し、親のサブタスクを再取得 |
| 500/通信エラー | 欄内に「時間をおいて再度お試しください」 |

## テストケース（技法注記付き）

- [代表値] 未完了サブタスクを含む一覧カード → `サブタスク 0/1` を表示
- [代表値] 完了済みと未完了を含む一覧カード → 完了数/総数を正しく表示
- [代表値] 編集モーダルでサブタスクを取得 → 作成順に表示
- [代表値] タイトル入力＋追加 → `POST` が正しい親ID/bodyで呼ばれ、一覧へ追加
- [境界値] 空タイトル/201文字 → エラー表示、`POST` は呼ばれない
- [状態遷移] チェックボックスON/OFF → `PATCH` が `completed` を送信し、表示状態を更新
- [代表値] 削除ボタン → `DELETE` が正しい親子IDで呼ばれ、一覧から消える
- [代表値] サブタスク0件 → 空状態メッセージを表示
- [代表値] 取得エラー → 再試行導線を表示
