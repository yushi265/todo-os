# ui-high-priority-polish: 高優先度UI改善

> TODOの高優先度項目を、既存のUI契約を保ったまま順番に実装するためのspec。

## 概要

モーダル・TODO行・状態変更に控えめなモーションを追加し、再利用効果の高いButtonだけをshadcn/ui方式のソース所有コンポーネントへ段階移行する。最後に複数の配色テーマを設定画面から切り替えられるようにする。

## 対象範囲

- 対象レイヤー: 表示層（ui）のみ（[ui.md](./ui.md)）
- 対象ドメイン: TODO一覧、モーダル、既存UI部品、テーマ設定
- 対象外: API、DB、認証、ルーティング、既存のTODO操作仕様の変更、未指定のshadcnコンポーネント追加

|---|---|---|---|---|
| 1 | UIモーション | AC-1 | — | 完了 |
| 2 | Buttonの段階導入 | AC-2 | AC-1 | 完了 |

## 受け入れ基準（AC）

- [x] **AC-1**: TODO一覧行、TODO作成/編集モーダル、削除確認ダイアログ、タグ管理モーダル、状態変更ボタンに控えめな表示・操作モーションが適用され、`prefers-reduced-motion: reduce`ではアニメーションと遷移が抑制される。
- [x] **AC-2**: 再利用効果を確認したうえで、主要なCTA・境界付きボタン・破壊的ボタンの一部が、プロジェクト内で所有するshadcn/ui方式のButtonコンポーネントを通じて表示される。既存のaria属性、disabled、クリック処理、44px以上のタッチ領域は維持される。
- [x] **AC-3**: 設定画面から複数のテーマを選択でき、選択したテーマが即時反映され、ページ再読み込み後もlocalStorageから復元される。未対応値やlocalStorage障害時は既定テーマへ安全にフォールバックする。

## アーキテクチャ / レイヤー間フロー

UIレイヤーのみで完結する。テーマ設定は`useTheme`が`document.documentElement`の`data-theme`とlocalStorageを管理し、CSSの既存セマンティックトークンをテーマ別に上書きする。ButtonはAPI契約を持たない表示プリミティブとして既存コンポーネントから利用する。

## エラー・ログ方針（横断サマリ）

| シナリオ | 表示層の挙動 |
|---|---|
| localStorageの読み書き失敗 | エラーを画面へ表示せず、メモリ上の選択と既定テーマで継続 |
| 未知のテーマ値 | 既定テーマへフォールバック |
| reduced motion有効 | CSSアニメーション・遷移を抑制 |

## 既存実装との関係（再利用 / 差分 / 衝突）

- 再利用: `index.css`のセマンティック色トークン、既存モーダルのフォーカス管理、既存のTailwindユーティリティ、テスト用のjsdom環境。
- 差分: CSSモーション定義、Buttonプリミティブ、テーマフックと設定モーダルを追加する。
- 衝突回避: DialogやRadixなど、既存のモーダル構造と責務が重複する依存は今回導入しない。

## 実装に効く制約

- 既存のAPI・props・aria属性・44pxタッチターゲットを変更しない。
- テーマは既存のセマンティックトークンを上書きし、コンポーネントへ色値を直接埋め込まない。
- Button導入は利用効果が確認できる範囲に限定し、全コンポーネントの一括置換をしない。
- 新しい挙動には先にテストを追加する。

## 判断根拠 / 未決事項

- shadcn/uiはランタイム依存の全面導入ではなく、ソースコードをプロジェクトが所有する方式を採用する。Buttonは複数画面で繰り返し使われるため効果があるが、Dialogは既存のレスポンシブ挙動とフォーカス管理があり、今回の置換効果が小さいため見送る。
- テーマは既存の色トークンを利用するため、APIやデータモデルを変更せず、利用者の設定はlocalStorageに限定する。
