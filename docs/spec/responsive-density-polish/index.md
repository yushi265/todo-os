# responsive-density-polish: 画面幅に応じた情報密度の調整

> 薄い実装 spec の入口。読み手は人間（Gate 1/2/3 承認者）。AI 実装エージェント（Codex）は [ui.md](./ui.md) を読む。

## 概要

PC・タブレット幅では文字サイズ・余白が大きく間延びして見える一方、スマホ幅ではそのままのサイズ感でよい、というユーザー指摘を受けて、`sm`（640px）以上の画面幅でのみフォントサイズ・padding・gapを1段階コンパクトにする。モバイル幅（`sm`未満）は現状のサイズ・余白を維持する（既存のモバイル向けデザインには手を加えない）。

## 対象範囲

- 対象レイヤー: ui のみ（[ui.md](./ui.md)）
- 対象ドメイン: TODO一覧画面の全コンポーネント（ヘッダー・フィルターバー・TODO行・各モーダル・タグ表示・完了トグル）のテキストサイズ・内部padding・gap
- 対象外（やらないこと）:
  - モーダル外枠のpadding構造（`p-4 sm:p-6`等、モバイルで詰めてPC以上で余裕を持たせる既存パターン）は「読みやすさのための構造的余白」として維持し、逆転させない
  - ローディング/エラー/空状態表示の余白（`py-10`等）は情報密度の対象外（状態表示であり一覧の密度とは性質が異なるため）
  - タッチターゲット最小44px（`min-h-11`/`min-w-11`）をいかなる画面幅でも44px未満に縮小すること
  - 完了トグル（`CompletedToggle`）のスイッチ本体（固定px値のトラック・ノブ）のサイズ変更（ラベルテキストのみ対象）
  - API・データスキーマ・レイヤー間インターフェースの変更

## ユニット計画

単一ユニット（本 spec で完結）。

## 受け入れ基準（AC）

- [ ] **AC-1**: ヘッダー（`TodoListPage.tsx`）の「タグ管理」ボタン・「+ 追加」ボタン・トースト通知が、`sm`以上でフォントサイズ`text-xs`・コンパクトなpaddingになる。`sm`未満は現状のサイズを維持する。
- [ ] **AC-2**: フィルターバー（`TodoFilterBar.tsx`）の検索input・フィルターチップ・「＋フィルター」ボタン・フィルターメニュー項目・ソートセレクト・方向切替ボタンが、`sm`以上でフォントサイズ`text-xs`・コンパクトなpadding/gapになる。`sm`未満は現状を維持する。
- [ ] **AC-3**: TODO一覧行（`TodoListItem.tsx`/`CompletedTodoListItem.tsx`）のメタ情報（優先度・期限・タグ）テキストと行間gap、およびカード自体の外枠padding（`p-4`）が、`sm`以上でコンパクトになる。`sm`未満は現状を維持する。既存の`sm:gap-4`（PC以上で拡大する現行値）は本ユニットの方針（PC以上でコンパクト化）と矛盾するため撤廃する。
- [ ] **AC-4**: 各モーダル（`TodoFormModal.tsx`/`TagManagementModal.tsx`/`DeleteConfirmDialog.tsx`）内のラベル・input・ボタンのテキストサイズが、`sm`以上で`text-xs`になる（モーダル外枠のpadding構造は対象外・現状維持）。`sm`未満は現状を維持する。`TagManagementModal.tsx`内で共有コンポーネント`ui/button.tsx`（`Button`）に置き換わっている箇所（閉じるボタン・追加ボタン）は、`Button`自体の`SIZE_CLASSES`にレスポンシブクラスを追加することで対応する（ユーザー判断・2026-08-15。個別箇所でのclassName上書きより、共有コンポーネント側での一元管理を優先）。
- [ ] **AC-5**: タグ選択（`TagMultiSelect.tsx`）・タグ管理（`TagManagementModal.tsx`内タグ行）のテキスト・ボタンpaddingが、`sm`以上でコンパクトになる。`sm`未満は現状を維持する。
- [ ] **AC-6**: 完了トグル（`CompletedToggle.tsx`）のラベルテキストが、`sm`以上で`text-xs`になる（スイッチ本体は対象外）。`sm`未満は現状を維持する。
- [ ] **AC-7**: 本ユニットで変更する全要素において、タッチターゲット最小44px（`min-h-11`/`min-w-11`）はいかなる画面幅でも維持される。

## アーキテクチャ / レイヤー間フロー

本ユニットはUIレイヤー内の見た目調整のみで、サービス層・データ層とのフローに変更はない。既存のAPI呼び出し・状態管理ロジックはそのまま維持する。

## エラー・ログ方針（横断サマリ）

見た目のみの変更であり、エラー・ログ方針に変更はない。既存の異常系挙動をそのまま継承する。

## 既存実装との関係（再利用 / 差分 / 衝突）

- **再利用**: 全コンポーネントの構造・props・イベントハンドラ・状態管理ロジックはそのまま。`index.css`の`@theme`色トークン・`@keyframes`は変更しない。
- **差分**: 本spec「受け入れ基準」に列挙した7項目。`TodoListItem.tsx`の既存`sm:gap-4`（design-conformance-polishで導入した値）を撤廃する点が唯一の「既存レスポンシブ値の変更」。
- **衝突**: なし。design-conformance-polishで確立したモーダルのボトムシート化構造・タッチターゲット44px制約とは矛盾しない（本ユニットはテキスト密度のみを対象とし、構造は変更しない）。

## 実装に効く制約

- タッチターゲット最小44px（`min-h-11`/`min-w-11`）はどの画面幅でも縮小しない（対象外節を参照）。
- `sm`未満（モバイル）のデフォルトクラス値は一切変更しない。変更は`sm:`プレフィックス付きクラスの追加・調整のみで行う。
- Tailwindのスケール上で「1段階小さい値」を選ぶ（例: `text-sm`→`sm:text-xs`、`py-2`→`sm:py-1.5`、`px-3`→`sm:px-2.5`、`gap-2`→`sm:gap-1.5`）。2段階以上の急激な縮小はしない。
- フォントサイズ未指定（ブラウザ既定16px相当）のボタン・inputには、まずデフォルト値として`text-sm`を明示追加し、その上で`sm:text-xs`を付与する（`sm`未満でも暗黙の16pxから14pxへ変わる点に注意。ただし対象範囲節の「`sm`未満は現状維持」はあくまで“意図した見た目”の話であり、フォントサイズが暗黙指定だった箇所を明示化すること自体は許容する。詳細はui.mdの判断根拠）。

## 判断根拠 / 未決事項

- **モーダル外枠paddingは対象外**: `p-4 sm:p-6`（モバイル狭い分は詰め、PC以上は余裕を持たせる）は一般的なモーダルデザインパターンであり、本ユニットの「PC以上でコンパクトに」という方針とは逆方向。無理に統一すると却ってPC版のモーダルが窮屈になるため、モーダルの外枠構造は現状維持とし、内部のテキスト・ラベル・input・ボタンのフォントサイズのみを対象にする。
- **フォントサイズ未指定要素への対応**: 現状「text-*クラスが無く暗黙で16px相当になっている」ボタン・inputが多数ある（TodoFormModalの各input、TodoListPageの複数ボタン等）。これらを`sm`未満でも無指定のままにすると、`sm:text-xs`だけを追加しても`sm`未満のサイズが変わらず「16px→sm:12px」という2段階の落差になってしまう。実装上の一貫性のため、`sm`未満のデフォルト値として`text-sm`(14px)を明示追加し、その上で`sm:text-xs`(12px)を加える2段階のクラス指定にする。これにより`sm`未満でも既存の周辺テキスト（`text-sm`が多数）と統一感が生まれる副次効果があるが、本ユニットの主目的（PC以上のコンパクト化）から外れないよう、`sm`未満のサイズ変化は「暗黙16px→明示14px」の範囲に留め、それ以上の意図的な変更はしない。
- **`TodoListItem.tsx`の既存`sm:gap-4`撤廃**: design-conformance-polish以前のユニットで導入された値で、「PC以上でgapを広げる」という今回の方針と逆方向。本ユニットで`gap-2`（`sm`でも変更なし、または`sm:gap-1.5`にコンパクト化）に統一する。
- **ローディング/エラー/空状態表示は対象外**: `py-10`等の大きな余白は、コンテンツが無い状態の視覚的な「間」を作る意図的なデザインであり、密な情報を並べる一覧・フォームとは性質が異なるため対象外とする。
